# C-5: Error Recovery and Learning from Failure

Forgetting is not failure — it's signal. This capability turns missed recalls into stronger memories by guiding users through reconstruction rather than passive re-exposure. Based on vision Step 7: "Repair failures productively."

---

## F-5.1: Failure Detection and Immediate Response

Detect a missed recall at the moment it happens and respond constructively — not punitively.

### E-5.1.1: Post-Failure Reveal
- S-5.1.1.1: As a user who forgets a name during a quiz, I immediately see the correct name and their photo together so I can reconnect the face and name
- S-5.1.1.2: As a user who forgets, I see my saved name image and interaction description so I can identify *why* the encoding failed

### E-5.1.2: Constructive Framing
- S-5.1.2.1: As a user who forgets, I see neutral, factual feedback ("Not quite — here's the cue") rather than negative language so I don't build a self-narrative of being bad with names
- S-5.1.2.2: As a user, I am prompted to reconstruct — not just re-read — the name image after a miss so active encoding replaces passive exposure

---

## F-5.2: Encoding Repair

Give users the tools to fix a weak image right at the point of failure.

### E-5.2.1: In-Quiz Image Edit
- S-5.2.1.1: As a user who missed a name, I can edit my name image or interaction description immediately within the quiz flow so I repair the encoding while the context is fresh
- S-5.2.1.2: As a user, my updated image is saved before the next question so the repair persists

### E-5.2.2: Weak-Image Queue
- S-5.2.2.1: As a user, contacts I've missed are automatically tagged for priority review so they surface more frequently until I stabilize
- S-5.2.2.2: As a user, I can view a "Needs Work" list of contacts with the most missed recalls so I can do targeted repair sessions

---

## F-5.3: Interval Reset and Recovery Scheduling

Ensure the SM-2 schedule responds aggressively to lapses so forgotten names get drilled back up.

### E-5.3.1: Lapse-Triggered Reset
- S-5.3.1.1: As a system, I reset a contact's review interval to 1 day when the user rates recall as "Forgot" so lapsed memories restart from the beginning
- S-5.3.1.2: As a system, I log each lapse event so the user can later see which contacts have lapsed most often

### E-5.3.2: Recovery Progress Visibility
- S-5.3.2.1: As a user, I can see a contact's lapse history so I understand how many times I've needed to rebuild a particular encoding
- S-5.3.2.2: As a user, I see a visual indicator when a previously lapsed contact reaches a stable review interval so I know the encoding has finally taken
