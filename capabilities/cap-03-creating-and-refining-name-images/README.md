# C-3: Creating and Refining Name Images

The heart of the memory palace method: turning an arbitrary name into a vivid, retrievable image and anchoring it to a stable locus. This maps directly to Steps 2–4 of the vision methodology.

---

## F-3.1: Name-to-Image Encoding

Help users convert a name into a concrete, imageable cue using sound-alikes, meaning, or syllable splitting.

### E-3.1.1: Guided Image Creation
- S-3.1.1.1: As a user adding a new contact, I am prompted to create a name image using one of three techniques (sound-alike, meaning-based, syllable split) so I have a starting point
- S-3.1.1.2: As a user, I can type a free-form description of my name image (e.g., "bent beam for Ben") so it's saved with the contact
- S-3.1.1.3: As a user, I see example encodings for common names so I understand what a good image looks like

### E-3.1.2: AI-Assisted Image Suggestions
- S-3.1.2.1: As a user, I can request a suggested name image from the app so I'm not stuck on an unfamiliar name
- S-3.1.2.2: As a user, I can accept, modify, or reject the suggested image so I stay in control of my own encoding

---

## F-3.2: Locus Assignment

Place the person in a specific, stable memory palace location so recall is spatially anchored.

### E-3.2.1: Palace and Locus Selection
- S-3.2.1.1: As a user, I can define named palaces (e.g., "My Office," "Weekly Meeting Room") so I have reusable spatial containers
- S-3.2.1.2: As a user, I can assign a contact to a specific locus within a palace (e.g., "door," "projector," "window") so their placement is explicit
- S-3.2.1.3: As a user, I can view all contacts placed in a given palace so I can mentally walk it before an event

### E-3.2.2: Locus Conflict Management
- S-3.2.2.1: As a user, I am warned if I try to assign two contacts to the same locus in the same palace so collisions don't create confusion
- S-3.2.2.2: As a user, I can move a contact to a different locus so I can resolve conflicts or improve placement

---

## F-3.3: Interaction Encoding

Capture the *interaction* between the image and the locus — the elaboration step that makes static images stick.

### E-3.3.1: Interaction Description
- S-3.3.1.1: As a user, I can write a brief interaction description (e.g., "Sarah's sari catches on the door handle") so the elaboration is saved and reviewable
- S-3.3.1.2: As a user, I am prompted to include motion or emotion in my interaction so the image is vivid enough to survive retrieval

### E-3.3.2: Image Refinement Over Time
- S-3.3.2.1: As a user, I can update my name image or interaction description after a failed quiz so I can repair a weak encoding
- S-3.3.2.2: As a user, I can flag an image as "weak" during a quiz so it surfaces for refinement in my next session
